## 1. 신규 판단 → 백엔드 연동 복원

### `frontend/app/judge/page.tsx`
- `api.judge()` 호출로 `POST /api/backend/judge` 실연동 (목업 결과 제거)
- `buildRequest()` 매핑:
  - 블렌딩 % → 0~1 fraction 정규화 (합이 100 아니어도 자동 보정)
  - 밀도 g/cm³ → kg/m³ (×1000)
  - priority 라벨 매핑: `balanced/safe` → `balance/safety`
- 결과 화면을 응답 데이터로 바인딩:
  - `decision`/`confidence` → 배지 + 헤드라인 + 아이콘 색상 분기
  - `predicted_cfpp_baseline` → 베이스라인 배너
  - `scenarios[]` → 3개 시나리오 카드(라벨별 색상·추천 배지)
  - `check_priority[]`, `similar_cases[]` → 우선순위/유사사례 리스트
  - `applied_heuristics[0]` → 헤드라인 문구
  - `rationale` → 시나리오 카드 하단 점선 구분선 + 문구
- 에러 화면 추가(백엔드 호출 실패 시 메시지 + 재시도 버튼)

## 2. 입력 폼 확장 — 모델 입력 1:1 매핑

### 레이아웃 재배치
- **왼쪽**: 블렌딩 구성 + 판단 조건 (목표 CFPP / 계절 / 탱크 이력 / 우선순위 / WAFI 첨가제 종류)
- **오른쪽**: 주요 성상 (CP, PP, 밀도 + n-파라핀 분포 + 방향족 + 황분 + 세탄)

### 주요 성상 입력 항목 9개로 확장
백엔드 `KeyMetrics` 스키마와 1:1 매핑. 모든 lab metric을 사용자가 통제 가능:

| 필드 | 단위 | step | 음수 |
|------|------|------|------|
| Cloud Point (참고용) | °C | 1 | 허용 |
| Pour Point (참고용) | °C | 1 | 허용 |
| 밀도 (15°C) | g/cm³ | 0.001 | 차단 |
| n-파라핀 C10–C15 | wt% | 0.1 | 차단 |
| n-파라핀 C16–C20 | wt% | 0.1 | 차단 |
| n-파라핀 C21+ | wt% | 0.1 | 차단 |
| 방향족 함량 | wt% | 0.1 | 차단 |
| 황분 | ppm | 0.1 | 차단 |
| 세탄 지수 | - | 0.1 | 차단 |

- CP/PP는 모델 입력 피처가 아님 → 라벨에 "(참고용)" 표시 + 섹션 상단 안내 문구
- WAFI 첨가제 종류는 판단 조건으로 이동, **WAFI 투입량 입력은 제거**(모델이 예측해야 할 출력)
- 계절 옵션 5개 → 2개(혹한기/동절기)로 축소

## 4. 합성 데이터 정합성 정리

CSV의 `target_cfpp`를 사용자가 수동으로 고정값(`winter=-18`, `deep_winter=-23`)으로 변경한 것을 반영하여 5개 항목 일괄 정리:

### 4-1. `synthetic_generator.py` 코드 동기화 (line 383~391)
- `rng.uniform()` 랜덤 샘플링 제거 → 계절별 고정값 하드코딩
- 주석을 새 평균값(`achievable CFPP mean -16.8 / -19.7`)에 맞춰 갱신
- 재생성 시 사용자 변경이 덮어쓰이지 않도록 함

### 4-2. CSV `decision` / `decision_noisy` 재라벨링
- `apply_labeling_rule`을 새 target 기준으로 다시 적용
- `decision_noisy = decision` 초기화 후 `inject_label_noise` 재호출
- 결과 분포:

| Season | normal | caution | risk |
|--------|--------|---------|------|
| winter (-18°C) | 30 | 84 | 137 |
| deep_winter (-23°C) | 10 | 60 | 179 |

- risk 비율 증가는 새 target이 더 공격적이라 발생 (운영 현실 반영)
- CFPP 회귀는 decision을 학습하지 않으므로 모델은 영향 없음

### 4-3. 프론트엔드 기본값 `targetCfpp`: -21 → **-23**
deep_winter 표준과 일치.

## 5. 유사 사례 UI 강화

### 5-1. 백엔드 응답 확장 — `backend/schemas/judge.py`
`SimilarCase`에 선택 필드 추가:
- `blend_components`, `key_metrics`, `target_cfpp`, `season`, `tank_history_flag`

`backend/services/recommend_service.py`의 RAG 경로와 numeric fallback 양쪽에서 Case row JSON을 응답에 채워 넣음.

### 5-2. 유사 사례 카드 표시 — `frontend/app/judge/page.tsx`
- 카드를 2줄 구조로 확장 (Case ID + 배지 + 유사도 / rule_summary)
- Case ID에 점선 밑줄 + 호버 툴팁(`<CaseTooltip>`)

### 5-3. 툴팁 — 가로형 표 + position:fixed
- 카드 `overflow:hidden`에 잘리는 문제 해결 — CSS-only hover에서 React state + `position:fixed` 방식으로 전환
- `getBoundingClientRect()`로 좌표 계산, `window.innerWidth/innerHeight` 기준 클램핑
- z-index 1000, 그림자 강화, `pointer-events:none`
- 표 구조: **세로형 → 가로형**(헤더 1행 + 값 1행)
  - **블렌딩 구성 (%)**: LGO/HGO/LCO/KERO/BIODIESEL 5열
  - **CFPP · WAFI · 컨텍스트**: CFPP / 실측 CFPP / WAFI 종류 / WAFI 투입량 / 계절
- 표시 라벨 정리:
  - "목표 CFPP" → **"CFPP"**
  - 계절: `winter` → **동절기**, `deep_winter` → **혹한기**

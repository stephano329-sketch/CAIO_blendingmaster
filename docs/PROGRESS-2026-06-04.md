## 2. 대시보드 전면 개편 (B안 풀버전)

기존 KPI 3장 + 로그 테이블 → KPI 6장 + 인사이트 3분할 + 차트 2×2 + 로그 테이블 구조로 확장.

차트 라이브러리: **recharts 2.13.3** ([frontend/package.json](frontend/package.json) 추가, `npm install` 완료).

### 2.1 KPI Strip (6장)

| 카드 | 데이터 |
|---|---|
| 오늘 처리 Batch | `stats.today_batch_count` |
| 이번 달 판단 | `stats.month_judge_count` |
| 이번 달 절감액(추정) | `stats.month_saving_man_won` |
| 예측 정확도 (MAE) | `actual_cfpp` vs `predicted_cfpp_after_wafi` 평균 절대 오차 |
| WAFI 절감률 | `(selected_wafi_ppm − actual_wafi) / selected_wafi_ppm` 평균 |
| 시나리오 분포 | min_cost / balanced / safe mini stacked bar |

그라데이션 배경 + Tabler 아이콘 + tone(blue/green/default) 옵션.

### 2.2 인사이트 3분할

- **오늘의 주의 알림**: 최근 30건 중 목표 CFPP 미달 / WAFI 제안 대비 +30ppm 이상 과투입 카운트. 좌측 border 빨강/초록.
- **AI 인사이트**: LCO 30% 이상 배치의 WAFI Type 채택률 자동 요약. 데이터 부족 시 fallback 문구.
- **오늘의 Batch 파이프라인**: `판단 완료 → 시나리오 선택 → 실측 입력 → 출하 완료` 4단계 카운트.

### 2.3 차트 그리드 2×2

## 4. AI 상담 답변 구조 개선

### 4.1 3섹션 응답 강제

LLM system prompt를 RAG-only(환각 금지) → 3섹션 구조로 재설계.

```
## 📚 RAG 기반 답변
(컨텍스트 인용 + [ID] 표시)

## ⚠️ 컨텍스트 한계
(검색된 문서에 빠진 항목 명시)

## 💡 일반 지식 보완 (RAG 외)
(업계 통용 기준, 정량 범위 + (모델 추정)/(업계 통용) 라벨)

ℹ️ 최종 의사결정은 담당자가 수행하세요. 일반 지식 보완 섹션은 검증 후 적용하세요.
```

- `max_tokens` 1024 → 1536 (3섹션 분량 확보)
- 사용자 프롬프트도 일반 지식 보완 섹션 적극 활용 지시

### 4.2 Next.js 프록시 타임아웃 우회

`max_tokens` 상향으로 응답 시간 증가 → 기존 `next.config.mjs` `rewrites` 프록시 30초 제한에서 500 발생.

해결: **Route Handler 신설**

- [frontend/app/api/backend/[...path]/route.ts](frontend/app/api/backend/%5B...path%5D/route.ts) — fetch 기반 프록시, GET/POST/PATCH/PUT/DELETE 지원
- `export const maxDuration = 120` (초)
- [frontend/next.config.mjs](frontend/next.config.mjs)에서 `rewrites` 제거

### 4.3 베테랑 지식 KB를 RAG 답변에 인용

`knowledge_entries` 테이블(베테랑 Q1~Q5 답변)이 그동안 인용되지 않던 문제 해결.

구현 ([backend/services/consult_service.py](backend/services/consult_service.py)):
- `_retrieve_knowledge(season)` 추가 — SQLite에서 최근 15건 로드 (season 필터)
- 각 entry를 `KB-XXXX` doc_id + 구조화 텍스트(블렌딩·CFPP/CP/PP·Q1~Q5)로 snippet 변환
- RAG snippet과 병합해 LLM 컨텍스트에 주입
- `ConsultResponse.citations`에도 KB 항목 추가 → 프론트 인용 박스에 doc_type `knowledge`로 표시
- 작성자 라벨 매핑: `junior` → "김 연구원", `veteran` → "이 부장"

LLM system prompt 보강 ([backend/engine/llm_client.py](backend/engine/llm_client.py)):
- "사례 ID(DIESEL-D-XXX), 문서 ID(A-XX, B-XX, C-XX), 베테랑 지식 ID(KB-XXXX)" 모두 인용 가능
- "베테랑 KB의 Q1 판단·Q5 메모는 정량 문서 못지않게 중요한 근거로 취급, 가능하면 KB 우선 인용"
- 인용 형식: `"KB-0003 (이 부장)"`

## 5. 데이터 흐름 요약 (최신)

### 5.1 AI 상담 (`/consult`)

```
사용자 query
  ↓
ChromaDB vector retrieval (top_k=5, 문서·사례)   ┐
SQLite knowledge_entries query (recent 15, season 필터) ┤
  ↓                                              ┘
LLM 컨텍스트 (RAG snippets + KB snippets)
  ↓
Claude Sonnet 4.6 — 3섹션 응답
  ↓
ConsultResponse {
  answer (마크다운 3섹션),
  citations: RAG 문서/사례 + KB-XXXX entries,
  used_llm, model
}
```

### 5.2 TS 사례 → 베테랑 지식 적재

```
frontend/lib/trouble-cases.json (8건)
  ↓
사용자가 Q1~Q5 답변
  ↓
POST /knowledge (case_id=TS-XXXX, q1~q5, author)
  ↓
SQLite knowledge_entries 테이블
  ↓ (다음 consult 호출 시 자동 인용)
AI 상담 답변에 KB-XXXX 인용
```

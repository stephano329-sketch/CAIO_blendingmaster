## 2. 신뢰도 공식 재설계

### `backend/services/recommend_service.py`의 `_decide()`
- 옛 공식 `0.5 + 0.1 × margin` 제거 (입력별로 거의 같은 값)
- 새 공식: 두 신호의 가중 평균
  - **신호 1 (agreement)**: top-3 유사 사례 중 최종 decision과 일치 비율
  - **신호 2 (margin_signal)**: decision별 마진 경계 거리
    - normal: 경계 3.0에서 멀수록 ↑
    - caution: 밴드 [1, 3]의 중심 2.0에서 최대
    - risk: 1.0 경계에서 더 음수일수록 ↑
- `confidence = 0.5 × agreement + 0.5 × margin_signal` (clamp 0.30~0.95)
- 검증: 0.30 ~ 0.62 등으로 입력별 분기 확인

## 5. AI 상담 실연동 + 컨텍스트 동기화

### 5-1. 백엔드 연동
- 목업 응답 제거 → `api.consult()` 호출로 실제 `/consult` 백엔드 사용
- 응답의 `answer`/`citations`/`used_llm`/`model` 모두 UI에 매핑
- 인용 태그(doc_type별 색상 + doc_id + section_title + 유사도)
- LLM 미사용 시 "RAG 인용 요약 (ANTHROPIC_API_KEY 미설정)" 표시

### 5-2. 신규 판단 → 상담 컨텍스트 자동 인계
- /judge 결과 화면의 "AI 상담 요청" 버튼이 sessionStorage에 컨텍스트 저장
- /consult 페이지가 마운트 시 컨텍스트 읽어 상단 바에 표시:
  - Batch ID (timestamp 기반 자동 생성) + decision 배지
  - LGO/HGO/LCO/Kero/Bio %, 목표 CFPP, 계절(한글), 베이스라인 CFPP
  - X 버튼으로 컨텍스트 해제
- 옛 스키마(`lco`만 있던 시절) 자동 폐기 가드
- 컨텍스트의 `season`을 `api.consult({ season })`로 전달 → 백엔드 RAG가 해당 계절 케이스 우선 검색

## 6. 목업 일제 제거 (4개 영역)

### 6-1. 대시보드 (`backend/routers/dashboard.py` 신규)
- `/judge` 호출 시 `DecisionLog`를 자동 저장 (`_persist_decision_log` best-effort)
- `GET /dashboard/stats` — 오늘/이번 달 batch 건수 + 절감액(`건수 × 26만원`)
- `GET /dashboard/recent-logs?limit=10` — 최근 의사결정 로그
- 프론트 `app/page.tsx` 전체 재작성: 하드코딩 `LOGS` 제거, API 호출, 빈 상태/로딩/에러 UI

### 6-2. 경험치 DB (`backend/models/knowledge_entry.py`, `backend/routers/knowledge.py` 신규)
- 새 모델 `KnowledgeEntry` (entry_id, case_id, season, blend, CFPP/CP/PP, q1-q5, author, created_at)
- `GET /knowledge?decision=&season=&limit=` + `POST /knowledge`
- 기존 `INITIAL_KB` 3건을 DB로 이관 (시드)
- 프론트 `app/kb/page.tsx` 전체 재작성: `INITIAL_KB` 제거, API 호출, 필드명/계절 라벨 매핑, 생성일시 포맷

### 6-3. 지식 추출 (`backend/routers/interview.py` 신규)
- `GET /interview/next-case?skip_done=true` — `KnowledgeEntry`에 없는 Case 우선 (전부 끝나면 첫 케이스 폴백)
- `Case.blend_components`(0~1 분율) → "NN%" 문자열, `key_metrics`의 `cfpp_measured`/`cfpp` 양쪽 처리
- 프론트 `app/interview/page.tsx`:
  - `IV_CASE` 하드코딩 상수 제거 → `iv` 상태 + `fetchCase()` + `useEffect` 자동 조회
  - "다음 케이스 →" 버튼이 응답 초기화 + 새 케이스 fetch
  - AI 초안 판단 배지/문구가 Case.decision 기반 (normal/caution/risk별 다른 힌트)
  - 로딩/에러 상태 처리

### 6-4. 지식 추출 저장 → 경험치 DB 반영
- `save()`가 `api.createKnowledge()` POST 호출
- `useUser()`로 현재 작성자(`junior`/`veteran`) 전달
- 저장 중/실패 인라인 상태 표시

### 의도적으로 유지된 항목
- AI 상담 batchId timestamp 기반 자동 생성 (운영 batch ID 체계 정해지면 변경)
- AI 상담 추천 질문 3개 (UI placeholder)
- 절감액 상수 `26만원/batch`

### 8-2. 배포 옵션 검토
GitHub 자체는 호스팅이 아님. 정리:
- **GitHub Codespaces**: 클라우드 dev container, FastAPI+Next.js 모두 실행 가능 — 개발/데모용
- **Streamlit Cloud**: 현재 구조와 비호환 (Streamlit 앱만 호스팅, 별도 포팅 필요)
- **GitHub Pages**: 정적만 가능, FastAPI 못 돌림
- **외부 호스팅 (push 연동)**: Railway, Render, Vercel, Fly.io 등
- 추천: 데모용 → Codespaces, 24/7 운영용 → Railway

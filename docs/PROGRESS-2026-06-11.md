## 1. 배포 방식 검토 (Streamlit Cloud → Vercel + Render)

사용자가 `share.streamlit.io`로 배포하려 했으나, 본 프로젝트는 **Next.js(프론트) + FastAPI(백엔드)** 분리 구조로 Streamlit 앱이 아니어서 Streamlit Cloud 배포 불가임을 진단.

- `streamlit` 의존성·진입 `.py` 부재 확인 ([backend/requirements.txt](../backend/requirements.txt))
- 대안 비교(A: Vercel+Render / B: Streamlit 재작성 / C: Docker 통합) 제시 → **A안 채택**

### 1.1 A안 배포 설정값 (가이드만 제공, 코드 변경 없음)

| 대상 | 플랫폼 | 핵심 설정 |
|---|---|---|
| 백엔드 | Render Web Service | Branch `main`, Root Directory 비움(리포 루트), Build `pip install -r backend/requirements.txt`, Start `uvicorn backend.main:app --host 0.0.0.0 --port $PORT`, env `ANTHROPIC_API_KEY`/`PYTHON_VERSION=3.12.7` |
| 프론트 | Vercel | Branch `main`, Root Directory `frontend`, Framework Next.js(자동), env `BACKEND_URL`=Render URL |

- 프론트는 [route.ts](../frontend/app/api/backend/[...path]/route.ts)가 서버사이드 프록시 → 브라우저-백엔드 CORS 미발생
- 알려진 함정: Vercel Hobby `maxDuration` 60초 제한(현재 120 설정) / Render 무료 512MB·슬립 / SQLite·ChromaDB 영속성 없음(읽기 데모 OK)

### 4.1 추출 완료 케이스 — Q1~Q5 읽기 전용 표시

- 상태 구조 변경: `extractedIds: Set<string>` → `extractedMap: Record<case_id, KnowledgeItem>` (Q1~Q5 데이터 보관, 케이스당 `created_at` 최신 1건)
- 타입은 `Awaited<ReturnType<typeof api.listKnowledge>>[number]`로 API 응답에서 자동 도출

- 저장 직후 낙관적 업데이트로 방금 입력값 즉시 반영
- 진행 상태 카드도 저장 엔트리 기준으로 표시

### 4.2 표시 방식 — 전체 선택지 + 선택 항목만 강조

- 선택된 것만 칩으로 나열 → **모든 선택지 표시, 선택 항목만 색상 강조**로 변경
- 입력 폼과 동일한 `.opt-btn`/`.sel-*` 스타일 재사용(`OptionRow` 컴포넌트), 차이는 클릭 불가(`cursor:default`)뿐
- Q1 색상: 정상=녹 / 주의=황 / 위험=적, Q2~Q4 선택=청색

### 4.3 비추출 케이스 — AI Q1~Q4 제안 (초록 점선)

- [trouble-cases.json](../frontend/lib/trouble-cases.json) 8개 사례에 `ai_suggestion: {q1,q2,q3,q4}` 추가(원인·해결 분석 기반 큐레이션)
- 입력 폼 옵션 버튼: 제안 항목이면 **초록 점선 + 스파클(✨)** 표시(`.opt-btn.ai-sug`)
- 자동 선택이 아닌 **시각적 제안** — 사용자가 클릭하면 정상 선택 색으로 전환(베테랑 실제 판단 캡처 취지 유지)
- 케이스 카드 하단 범례: `✨ 초록 점선 = AI 제안 (참고용, 직접 선택하세요)`

## 5. A안 배포 실행 (Vercel + Render)

검토만 했던 A안을 실제 배포까지 완료. **정상 동작 확인됨.**

### 5.1 결정 사항

| 항목 | 선택 |
|---|---|
| Vercel 플랜 | Hobby(무료) → 함수 타임아웃 60초 한도 |
| Render 설정 | render.yaml (Blueprint, IaC) |
| DB 영속성 | 임시(읽기 데모) — 외부 DB 미전환 |

### 5.2 리포 준비 (커밋 `f422bf7`)

- [render.yaml](../render.yaml) 신설 — Render Blueprint. `type: web`, `runtime: python`, `plan: free`, `branch: main`, build `pip install -r backend/requirements.txt`, start `uvicorn backend.main:app --host 0.0.0.0 --port $PORT`, `healthCheckPath: /health`, `ANTHROPIC_API_KEY`는 `sync:false`(대시보드 시크릿 입력)
- [route.ts](../frontend/app/api/backend/[...path]/route.ts) — `maxDuration` 120 → **60** (Vercel Hobby 한도)

### 5.3 배포 구조

```
브라우저 → Vercel(Next.js, Root Directory=frontend, env BACKEND_URL)
              │ /api/backend 서버사이드 프록시
              ▼
          Render(FastAPI) → blending_master.db(SQLite) + chroma_db/(ChromaDB)
```

- 프론트(Vercel)에는 DB 없음. DB는 **Render 컨테이너 로컬 디스크**에 위치(git 커밋본을 클론 시 포함).
- 읽기(사례·KB·RAG)는 정상. 단 Render 무료 디스크는 휘발성 → 재배포·재시작·슬립 시 git 커밋 상태로 리셋(런타임 입력 데이터 비영속).
- `main` push 시 Vercel·Render 모두 자동 재배포.

### 5.4 운영 주의

- Render 무료: 15분 무요청 시 슬립 → 첫 호출 지연(시연 직전 워밍업 권장), 512MB 메모리(빌드 OOM 시 Starter 상향)
- Vercel Hobby: AI 상담 응답 60초 초과 시 타임아웃(길어지면 Pro 전환)
- 입력 데이터 영구 보존 필요 시: Render Persistent Disk(유료) 또는 외부 DB 전환
